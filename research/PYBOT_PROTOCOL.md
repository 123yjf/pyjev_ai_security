# Original PyBot comparison · protocol fixed before evaluation

**Question.** Can each publicly exposed interface return a usable label on the same texts? This is a task-interface comparison, not a general comparison of language understanding, a detector of model identity, or a human judgment of PyBot's free-form advice.

## Systems and test units

- Original [huggingface/pybot](https://github.com/huggingface/pybot/tree/7d63c7fbebb44c7e466e5c8b5c1f341ab767929e), commit `7d63c7fbebb44c7e466e5c8b5c1f341ab767929e`, tree `bot` at `d496fee8e0ec8fc21229f223239c22bdbcc0be74`. Check `pybot.py` and all 528 Python files under `bot/`. No replacement responder, fine-tuning, rule changes or external classifier. The adapter calls the official single-turn `pybot.answer(runtime, prompt, {})`. Its only output processing is the predeclared label parser. A harmless CLI parity probe is required.
- PyJev 0.1.0: checksummed checkpoint 323 plus intent head. For speech acts read `speech_act`; for binary injection read the conservative `review` route; no use of a gold label or source field in predictions.
- **Office:** all 320 authored Chinese texts, labels mention / act / unclear. These are 120 matched pairs plus 80 unspecified examples, not 320 independent natural conversations. Classification is about the embedded act (e.g., translating an instruction is not performing it).
- **External:** all 353 publisher-labelled translation-context cases, 153 injected and 200 normal. **Historical:** all 1,384 Chinese rows of zh-ipi-bench v3, 1,323 injected and 61 normal. Use exact files in [replay.py](replay.py); no past cases relabelled and no subsampling.
- Same underlying text, labels and denominator for both systems. PyBot's ordinary product is a general rule-based chat interface; it needs a task instruction to produce labels. Use the fixed English + Chinese task framing in [compare_pybot.py](compare_pybot.py), followed by the original text verbatim. PyJev's native API takes the original text directly. These are **not** identical serialized prompts. No prompt search, model calls, repair/retry, translating of test texts, or cherry-picked prompts.

## Scoring and environment

1. Fix seed 20261124 and Python hash seed 0, use fresh empty memory and a fresh fork per example from an unqueried, preloaded official runtime. Match the original seeded CLI on a neutral office example. Run without network, shared credentials, command tools or writable host mounts for model inference. Only structured outcome counts are exported. A wall-clock limit of 30 seconds per PyBot turn is applied; separate timeout/error/no-label.
2. Accept a single declared canonical label or its published English/Chinese equivalent (including one letter choice), optionally with surrounding punctuation, the single prefix “label/answer/标签/答案”, or an object with the single field `label`. No substring detection, no inferring a verdict from refusals/long explanations; the exact parser and prompts are part of the protocol. Native “unclear” is a **valid semantic class**; free-form nonlabels are not “unclear”, “benign” or “incorrect meaning”.
3. For each dataset report N, completed calls, valid labels/N, correct labels/N (end-to-end *structured task completion*), confusion by gold label and the count of no-label/timeout/error. Report correctness among valid labels only if any exist. False-positive/positive-detection ratios are conditional on **valid labels from the corresponding class**; an empty denominator is **N/A**, not zero. Do not use an invalid reply as evidence that a system correctly dismissed a security issue.
4. The first full frozen evaluation is reported, including failures. No selecting a prompt/seed after inspecting scores. This benchmark is newly run on existing known cohorts, **not** a new independent blind test of PyJev. Source texts and unrestricted chatbot replies are not published. The runtime can share read-only imported code across forks, not conversations. Times are not a speed benchmark.
